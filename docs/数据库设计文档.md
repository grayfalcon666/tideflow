## 4. comments 表（两层楼中楼，支持回复二级评论）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | uint | PK | 主键 |
| video_id | uint | INDEX, NOT NULL | 视频 ID |
| author_id | uint | INDEX, NOT NULL | 评论 / 回复发布者 ID |
| username | varchar(255) | INDEX | 评论 / 回复发布者用户名 |
| root_id | uint | NOT NULL, DEFAULT 0 | **根评论 ID**（固定为一级评论 ID，0 = 一级评论，所有回复都继承一级 ID） |
| parent_id | uint | NOT NULL, DEFAULT 0 | **直接父 ID**（0 = 一级评论，一级 ID = 回复一级，二级 ID = 回复二级） |
| content | text | NOT NULL | 评论 / 回复内容 |
| created_at | datetime | INDEX | 创建时间 |
| deleted_at | datetime | DEFAULT NULL | 软删除时间 |

**索引：**
- idx_comments_video_root (video_id, root_id)：快速查询视频下所有一级评论及归属的回复
- idx_comments_parent_id (parent_id)：快速查询直接父级的回复

**核心设计规则（严格两层，无无限嵌套）：** 
1. **一级评论**：root_id=0，parent_id=0（顶层评论，无父级） 
2. **回复一级评论**：root_id = 一级评论 ID，parent_id = 一级评论 ID（标准二级回复）
3. **回复二级评论**：root_id=**继承一级评论 ID**，parent_id = 二级评论 ID（自动挂靠根一级评论，不生成三级） 
4. **层级限制**：全局只有**一级评论 + 二级回复**两层，回复二级评论不会产生新层级
